# Intent: Ed25519 / Curve25519 PGP keys for encryption and signing

`zfsbackup` encrypts and signs volumes with OpenPGP through
`golang.org/x/crypto/openpgp` (`pgp/pgp.go`, `files/volumeinfo.go`,
`cmd/root.go`). That package is deprecated and frozen: it only understands
RSA, DSA, ElGamal, ECDSA and (parse-only) ECDH keys. A keyring holding the
keys GnuPG has generated by default since 2.3 (2021) -- an Ed25519 signing
key with a Curve25519 (`cv25519`) encryption subkey -- fails to load:

```
Could not load public keyring due to an error - openpgp: unsupported feature: public key type: 22
```

We want `--publicKeyRingPath` / `--secretKeyRingPath` to accept modern
keyrings (Ed25519 + Curve25519, including the RFC 9580 "v6" variants newer
tools emit) for `--encryptTo` and `--signFrom`, while every existing RSA
keyring and every backup already written keeps working unchanged, and
volumes remain decryptable/verifiable with stock `gpg`.

Approach: swap the frozen package for its maintained, API-compatible fork
`github.com/ProtonMail/go-crypto/openpgp` (v1 API), re-vendor, and add the
test coverage the crypto path has never had (unit, GnuPG interop, e2e).
Details in `plan.md`.
